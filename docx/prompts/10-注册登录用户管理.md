任务：实现注册、登录、登出与用户管理模块。

背景：
- 项目已有 setSessionCookie()、getCurrentUser()、requireRole()、recordAudit()。
- 已有 Role 枚举（ADMIN / PM / MEMBER / QA）。
- 已有 AuditLog 表和 MySQL 触发器（不可更新、不可删除）。
- 但没有任何登录 API、登录页面、注册流程、用户管理 API。
- 所有受保护路由（/audit、AI 建议采纳、任务分配等）目前无法通过真实用户流程验证。

业务约束（医疗软件场景）：
- 本项目只使用合成数据，禁止真实患者信息（PHI）。
- 医疗软件的账号体系通常由管理员统一创建，自助注册需要审批或邀请码。
- 密码必须哈希存储，禁止明文、禁止可逆加密。
- 登录失败不能暴露"邮箱是否存在"，统一返回"邮箱或密码错误"。
- 会话必须可失效、可审计。
- 所有认证相关操作必须写入审计日志。

## 一、范围定义

本模块包含：
1. 用户注册（自助注册 + 管理员创建两条路径）
2. 登录 / 登出
3. 会话管理（获取当前用户、会话过期）
4. 用户管理 API（列表、创建、禁用、角色变更）
5. 密码修改（用户本人）
6. 登录页面、注册页面、用户管理页面

本模块不包含：
- 第三方 OAuth / SSO（预留接口，不实现）
- 邮件发送、短信验证（预留，不实现）
- 密码找回（预留 token 表，不实现流程）
- 多因素认证（MFA）

## 二、数据模型

新增或扩展以下 Prisma model：

### User（扩展已有）
新增字段：
- passwordHash: String（bcrypt 或 argon2 哈希，必须）
- status: UserStatus（ACTIVE / DISABLED / PENDING，默认 PENDING）
- lastLoginAt: DateTime?（最后登录时间）
- failedLoginCount: Int（默认 0，连续失败计数）
- lockedUntil: DateTime?（锁定到期时间）

已有字段保留：id, email, name, role, createdAt

### Session（新增）
字段：
- id: String（UUID）
- userId: String（外键 User）
- tokenHash: String（会话 token 的哈希，不存明文）
- expiresAt: DateTime
- createdAt: DateTime
- revokedAt: DateTime?（登出或强制失效时间）
- ip: String?
- userAgent: String?

要求：
- 一个用户可以有多个活跃 session（多设备）。
- 登出只撤销当前 session，不影响其他设备。
- Session 过期或撤销后不可再用。

### PasswordResetToken（预留，不实现流程）
字段：
- id, userId, tokenHash, expiresAt, usedAt, createdAt
- 本阶段只建表和类型，不实现发送和验证流程。

### 新增 Enum
- UserStatus: ACTIVE, DISABLED, PENDING

## 三、API 设计

所有 API 输入必须用 Zod 校验，输出统一 JSON 格式。

### 认证相关
- POST /api/auth/register
  - 输入：email, password, name, inviteCode?（可选邀请码）
  - 逻辑：
    - 若已存在同 email，返回统一错误（不暴露是否已注册）
    - 密码强度校验：至少 8 位，含字母和数字
    - 创建用户，status 默认 PENDING（无邀请码）或 ACTIVE（有有效邀请码）
    - 写审计：USER_REGISTERED
  - 权限：公开

- POST /api/auth/login
  - 输入：email, password
  - 逻辑：
    - 统一错误信息："邮箱或密码错误"
    - 检查 status：DISABLED 拒绝，PENDING 提示"等待管理员激活"
    - 检查 lockedUntil：锁定中拒绝并提示剩余时间
    - 验证密码失败：failedLoginCount +1，达到阈值（如 5 次）锁定 15 分钟
    - 验证成功：failedLoginCount 归零，lastLoginAt 更新，创建 Session
    - 写审计：LOGIN_SUCCESS 或 LOGIN_FAILED（含 IP、userAgent）
  - 权限：公开

- POST /api/auth/logout
  - 逻辑：撤销当前 Session，清除 cookie
  - 写审计：LOGOUT
  - 权限：需登录

- GET /api/auth/me
  - 返回当前用户信息（不含 passwordHash）
  - 权限：需登录

### 用户管理
- GET /api/users
  - 支持筛选：role, status, keyword
  - 分页：page, pageSize
  - 权限：ADMIN（PM 只能看，不能改，可选）

- POST /api/users
  - 管理员创建用户
  - 输入：email, name, role, initialPassword
  - 创建后 status = ACTIVE
  - 写审计：USER_CREATED_BY_ADMIN
  - 权限：ADMIN

- PATCH /api/users/[userId]/role
  - 修改用户角色
  - 写审计：PERMISSION_CHANGED（包含 before / after）
  - 权限：ADMIN
  - 不能修改自己的角色（防止误操作）

- PATCH /api/users/[userId]/status
  - 启用 / 禁用用户
  - 禁用时：撤销该用户所有 Session
  - 写审计：USER_STATUS_CHANGED
  - 权限：ADMIN
  - 不能禁用自己

- PATCH /api/users/me/password
  - 用户修改自己的密码
  - 输入：currentPassword, newPassword
  - 验证当前密码后更新
  - 更新成功后撤销该用户其他所有 Session（保留当前）
  - 写审计：PASSWORD_CHANGED
  - 权限：需登录

## 四、安全要求

1. 密码哈希使用 bcrypt（cost ≥ 12）或 argon2id。禁止明文、MD5、SHA1。
2. 会话 token 使用 crypto.randomBytes 生成，数据库只存 tokenHash。
3. Session cookie 使用 HttpOnly + SameSite=Lax + Secure（生产环境）。
4. 登录失败统一返回："邮箱或密码错误"，不区分"用户不存在"和"密码错误"。
5. 登录失败次数达到 5 次锁定 15 分钟；锁定信息不暴露给攻击者更多细节。
6. 角色变更、状态变更、密码修改必须写审计，且包含 before / after。
7. 禁止在日志、审计、响应中输出 passwordHash。
8. 禁止硬编码任何密码到源码中；seed 密码从环境变量或常量文件读取。
9. 所有涉及多表写入的操作必须在事务内完成。

## 五、页面设计

### /login
- 邮箱、密码输入框
- 登录按钮
- 错误提示（统一："邮箱或密码错误"）
- 链接到 /register
- 登录成功后重定向到首页或原目标页

### /register
- 姓名、邮箱、密码、确认密码
- 邀请码（可选）
- 提交后：
  - 若有邀请码：status = ACTIVE，提示"注册成功，请登录"
  - 若无邀请码：status = PENDING，提示"注册成功，等待管理员激活"
- 链接到 /login

### /users（仅 ADMIN）
- 用户列表：姓名、邮箱、角色、状态、最后登录时间
- 筛选：角色、状态、关键词
- 操作：修改角色、启用/禁用、创建用户
- 创建用户弹窗：姓名、邮箱、角色、初始密码

### /profile（需登录）
- 显示当前用户信息
- 修改密码表单
- 登出按钮

## 六、审计事件清单

以下操作必须写入 AuditLog：

| action | 触发时机 | 关键字段 |
|--------|---------|---------|
| USER_REGISTERED | 自助注册 | email（脱敏）、role、status |
| USER_CREATED_BY_ADMIN | 管理员创建 | actorId、targetUserId、role |
| LOGIN_SUCCESS | 登录成功 | actorId、ip、userAgent |
| LOGIN_FAILED | 登录失败 | email（脱敏）、ip、reason |
| LOGOUT | 登出 | actorId |
| PASSWORD_CHANGED | 修改密码 | actorId |
| PERMISSION_CHANGED | 角色变更 | actorId、targetUserId、before、after |
| USER_STATUS_CHANGED | 状态变更 | actorId、targetUserId、before、after |

email 脱敏规则：只保留首字符和域名，如 `t***@example.com`。

## 八、验收标准

功能验收：
- 用 admin@medpm.local / test1234 登录成功，重定向到首页。
- 用错误密码登录，返回"邮箱或密码错误"。
- 连续 5 次失败后，账号锁定 15 分钟。
- 用 member@medpm.local 登录后访问 /audit，被拒绝（403 或重定向）。
- 用 pending@medpm.local 登录，提示"等待管理员激活"。
- 用 disabled@medpm.local 登录，被拒绝。
- ADMIN 登录后访问 /users，能看到用户列表。
- ADMIN 修改某用户角色，AuditLog 出现 PERMISSION_CHANGED 记录。
- 用户修改密码后，其他设备的 Session 失效。
- 登出后再次访问受保护路由，重定向到 /login。

审计验收：
- 登录成功、登录失败、登出、注册、角色变更、状态变更、密码修改均在 AuditLog 有记录。
- 登录失败记录包含 IP 和 userAgent，但不包含明文密码。
- 角色变更记录包含 before 和 after 的完整角色。

安全验收：
- 数据库中 passwordHash 是 bcrypt 哈希，不是明文。
- Session 表中 tokenHash 是哈希，不是明文 token。
- 响应 JSON 中不包含 passwordHash 字段。
- 未登录访问 /api/users 返回 401。
- MEMBER 访问 /api/users 返回 403。

测试验收：
- 单元测试覆盖：密码哈希、密码强度校验、锁定逻辑。
- 集成测试覆盖：注册、登录、登出、角色变更、状态变更。
- 集成测试覆盖：登录失败锁定、PENDING 拒绝、DISABLED 拒绝。

## 十、禁止事项

- 禁止明文存储密码。
- 禁止在响应中返回 passwordHash。
- 禁止硬编码密码到源码中。
- 禁止在登录失败时区分"用户不存在"和"密码错误"。

- 禁止为"能跑"而绕过测试。
- 禁止引入真实用户数据。
- 禁止把登录逻辑写进 middleware 而破坏现有 API 的权限校验模式（保持 handler 内 requireRole 的现有约定）。
