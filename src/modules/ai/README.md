# AI agents

Keep model integration and agent workflows in this module. The WBS agent uses LangChain ChatOpenAI, ChatAnthropic, or ChatGoogleGenerativeAI selected by `AI_PROVIDER`/`AI_MODEL`. Text embeddings use OpenAI `text-embedding-3-small` at 1536 dimensions, so `OPENAI_API_KEY` is required for vector retrieval even when another chat provider is selected.

The WBS prompt sends the user's requirement, completed-task history and retrieved document evidence from the current project. Document evidence is treated as untrusted input; cited chunk IDs must belong to the supplied evidence. The UI requires confirmation that inputs contain synthetic data only, and the API rejects common email, phone, and labeled patient-identifier patterns. This is a guard against accidental disclosure, not a substitute for synthetic-only handling. The agent records a redacted request summary, provider/model, retrieval IDs, retrieval degradation, model latency, and review outcome. Every proposed task is a separate `AiSuggestion` in `PENDING`; no generation path writes a `Task`. PMs accept or reject tasks one at a time. A task with prerequisites can be accepted after those prerequisite suggestions have been accepted. Role authorization is rechecked under a user-row lock when persisting WBS/compliance output and reviewing WBS/risk suggestions.

Milvus failures and empty/unindexed collections fall back to parameterized MySQL keyword search over completed tasks with actual hours. History fallback queues `SyncFailure` work for an explicit PM history-sync request; it does not perform remote indexing in the fallback path. Document chunk indexing runs in the document worker, with bounded retries and explicit retry support. Retrieval provenance is audited before sources are returned. If a model is unavailable or returns invalid output, the agent records the failure and asks the PM to create tasks manually.

The risk agent supports manual PM scans and a durable scheduled worker with personal notifications. Deterministic rules inspect approaching or overdue tasks, unfinished prerequisites, historical delay rates and configured weekly capacity across projects. Each warning records its task, evidence and relevant sources. Warnings are `RISK` suggestions in `PENDING`; repeated scans deduplicate identical pending evidence, while changed evidence can produce another warning for the same task. PM decisions change only the suggestion status and create an audit event; task status is never changed. Planning snapshots enforce limits of 5,000 project tasks, 1,000 members and 20,000 cross-project unfinished tasks. Cross-project contributor IDs are filtered from visible risk evidence. See `docs/planning-capacity.md` and `docs/risk-scheduler.md` for allocation semantics, failures and worker setup.
