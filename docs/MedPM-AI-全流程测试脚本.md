## 测试路线与环境准备

建议使用四个独立浏览器配置文件或独立浏览器上下文分别登录，避免同一浏览器标签页共享 Cookie 后误判角色。密码沿用现有本地密码，不写进测试文档、截图或抓包附件。

| 角色 | 账号 | 本次主要职责 |
| :--- | :--- | :--- |
| PM | `pm@medpm.local` | 任务、排期、AI 建议确认、文件提交、会议和申请验收 |
| MEMBER | `member@medpm.local` | 执行本人负责且未完成的任务 |
| QA | `qa@medpm.local` | 独立审批交付物、合规审查、审计与导出 |
| ADMIN | `admin@medpm.local` | 用户管理、授权、最终独立归档、全局统计 |

按以下顺序执行，避免项目冻结后无法继续测试：

1. **先核验基线**：0.1–0.5，尚未修改数据时核对精确数量。
2. **先测风险分支**：5A.1–5A.8。在仍有缺口时验证特权送审、阻断批准，然后撤回，恢复 ACTIVE。
3. **再走执行主线**：模块一至四；AI 采纳、行动项转任务会增加任务数量，之后不得继续按固定 14 条判错。
4. **最后正常结项**：完成所有实际任务与行动项，执行 5B，再执行归档后的 5C。
5. **异常验证单独运行**：模块六使用独立测试库或专用故障环境；归档不可重新打开，需重跑准备脚本获得新快照才能复位。

初次准备或需要复位时，由测试人员手动执行以下命令。本文件本身不会执行它们：

```powershell
# 仅预览：不修改数据库和 .env
node scripts/prepare-hospital-demo.mjs

# 需要复位才执行：新建快照，保留原库及审计，不在旧库删数据
node scripts/prepare-hospital-demo.mjs --apply

# 停止旧开发服务后，在具备所需网络权限的正常终端启动
pnpm dev

# 可选：账号、六个页面和真实 PDF 下载的只读业务冒烟
# 会产生正常登录/登出和下载审计，不增删改任务、会议或交付物
node scripts/verify-hospital-demo.mjs
```

MySQL、MinIO、Milvus、Embedding API 与当前 Chat 模型应可访问；新上传 PDF 和会议知识库同步还需要现有文档 Worker。外部模型或 Worker 不可用时标记“阻塞”，不要将同步中当作已入库，也不要把合成预置解析当作本次 MinerU 云解析成功。

记下本轮项目 UUID 为 **P**，SIT 任务 UUID 为 **T**，会议 UUID 为 **M**；均从当前页面 URL 或 Network 请求取得。不要复用上一次快照的 UUID。

## 附录 B：限定范围的数据库证据检查

只在明确的合成测试库执行；先把 UUID 替换为本轮真实值。每个写入探针单独执行，并在客户端报错后手动执行 ROLLBACK；不要添加 COMMIT，不要使用无 WHERE 的 UPDATE/DELETE。

```sql
SELECT DATABASE();
SET @project_id = '替换为当前项目UUID';
SET @task_id = '替换为该项目一个任务UUID';

-- 必须查到恰好一条正确项目、已归档任务记录，才继续冻结探针。
SELECT p.name, p.status, t.id, t.title, t.status
FROM Project p JOIN Task t ON t.projectId=p.id
WHERE p.id=@project_id AND t.id=@task_id;

-- 归档冻结：同值 UPDATE 也应触发 BEFORE UPDATE，不改任务实际含义。
START TRANSACTION;
UPDATE Task t JOIN Project p ON p.id=t.projectId
SET t.description=t.description
WHERE t.projectId=@project_id AND t.id=@task_id AND p.status='ARCHIVED';
-- 预期 ER_ARCHIVED_PROJECT；若未报错也必须回滚并登记失败。
ROLLBACK;

-- 查看签名证据，不查询密码字段。
SELECT id, entityId, action, createdAt,
       JSON_UNQUOTE(JSON_EXTRACT(`after`,'$.signatureReason')) AS signatureReason,
       JSON_UNQUOTE(JSON_EXTRACT(`after`,'$.completedAt')) AS signedCompletion
FROM AuditLog
WHERE projectId=@project_id AND entityType='Task'
  AND entityId=@task_id AND action='TASK_SIGNED_AND_COMPLETED'
ORDER BY createdAt;

-- 先确认此审计属于当前项目，再做一次独立事务的删除探针。
SET @audit_id = '替换为上一查询的一条审计UUID';
SELECT id, action FROM AuditLog WHERE projectId=@project_id AND id=@audit_id;
START TRANSACTION;
DELETE FROM AuditLog WHERE projectId=@project_id AND id=@audit_id;
-- 预期审计不可删除错误；即使没有报错，也不得提交。
ROLLBACK;
```

审计/体检触发器的具体数据库错误名以当前迁移为准；验收依据是写入被触发器拒绝、原值不变及应用映射正确，不能只核对某一句报错文案。
