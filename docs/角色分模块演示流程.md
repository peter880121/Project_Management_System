# MedPM AI 按角色分模块演示流程

更新日期：2026 年 10 月 16 日。适用于当前本地版本及第一批验收整改后的页面。

本手册按 PM、MEMBER、QA、ADMIN 的工作职责组织演示。主线是一次合成医疗软件登录功能的交付：PM 建立需求和计划，成员执行，QA 验证并检查追溯，管理员管理访问权限。每个模块均给出入口、操作、预期结果和讲解要点，可单独演示，也可串成完整业务闭环。

当前页面已统一主导航。项目列表突出项目阶段，项目看板突出任务状态；创建项目和创建任务使用独立页面，WBS 与风险也各有独立入口。演示时通过页面入口操作，不要求观众输入项目 UUID 或业务网址。WBS 建议必须经 PM 确认，风险不会自动改变任务状态；合规摘要的采纳也不等于发布批准。

## 一 演示范围与角色分工

| 角色 | 建议展示模块 | 不应误演示的能力 |
| --- | --- | --- |
| PM | 项目与成员、需求与任务、PDF 与 RAG、WBS、排期与容量、风险与通知 | 不以 PM 身份维护测试用例、复核合规摘要或生成合规导出 |
| MEMBER | 查看已授权项目、执行本人任务、填写实际工时、查看任务详情和来源 | 不创建项目、不采纳 AI 建议、不修改他人任务、不管理用户 |
| QA | 测试用例、需求版本复核、审计查询、合规摘要及发现项复核、CSV/JSON 导出 | 不以 QA 身份采纳 WBS、调整排期或分配任务 |
| ADMIN | 创建或激活账号、修改角色、禁用与恢复、查看审计、维护项目成员 | ADMIN 不等同于 PM 或 QA：当前 WBS、风险操作由 PM 执行，合规摘要复核由 QA 执行 |

系统角色决定“能做什么”，项目授权决定“在哪些项目做”。非 ADMIN 用户需要是项目负责人或有效项目成员；仅具备 QA、MEMBER 等角色，并不自动获得所有项目访问权。

## 二 开场准备

### 2.1 服务与账号

1. 确认 MySQL 及已部署的数据库迁移可用。已有环境不重新执行 seed、不重置数据库。
2. 在项目根目录运行 `pnpm dev`，打开 `http://localhost:4000`。若提示端口占用，先核实是否已有本项目服务，不重复启动。
3. PDF 上传与导出需要 MinIO；云端解析需要已配置 MinerU，并在独立终端运行 `pnpm documents:worker`。
4. 语义检索需要 embedding 配置和 Milvus；WBS 需要已配置的模型服务。检查实际配置，不在录屏或文档中展示密钥。
5. 自动风险扫描需要独立运行 `pnpm risks:worker`。只演示手动扫描时不依赖该后台进程。

| 角色 | 默认合成账号 | 使用说明 |
| --- | --- | --- |
| ADMIN | `admin@medpm.local` | 用户管理及全局审计 |
| PM | `pm@medpm.local` | 建立演示项目、组织交付 |
| MEMBER | `member@medpm.local` | 执行本人被分配的任务 |
| QA | `qa@medpm.local` | 测试、追溯与合规审查 |

上述为 seed 约定账号，正式演示前确认仍为 ACTIVE。初始密码来自本地 `LOCAL_DEV_SEED_PASSWORD`；若曾修改，以实际密码为准。本手册不记录密码，也不建议为演示重置已有账号。

**角色切换方式：**最稳妥的是在同一个 Edge 窗口中使用主导航“登出”，再登录下一角色。普通标签页共享登录态，不能用四个标签页表示四个角色；同一 InPrivate 会话内的标签页也可能共享登录态。确需同时展示时使用独立浏览器配置文件。此前 Edge 无痕窗口偶发切换至普通窗口的问题尚未定位，正式录屏优先使用单窗口顺序切换。

### 2.2 统一演示数据

为避免改写之前的走查数据，优先由 PM 新建 `DEMO-20261016-ROLE-01 登录与审计交付`；当天重演时替换日期或序号。若复用已有 `DEMO-20261016-02 医疗软件登录与审计交付`，先确认当前需求版本、任务状态和成员授权，不假定它仍为空项目。

| 对象 | 建议名称或内容 | 演示作用 |
| --- | --- | --- |
| 主需求 | `REQ-DEMO-01 登录失败锁定与审计追踪` | 需求、任务、测试的共同关联点 |
| 主任务 | `TASK-DEMO-01 实现登录失败计数与锁定` | 用于成员执行、工时和测试闭环 |
| 故意留缺口任务 | `TASK-GAP-01 校验审计事件字段` | 首次不关联需求，供合规 Agent 发现并再次验证整改 |
| 测试用例 | `TC-DEMO-01 连续失败达到阈值后锁定` | 由 QA 创建，先 NOT_RUN，执行后 PASSED |
| 需求 PDF | `synthetic-medsoft-requirements-v1.pdf` 或其他已备好的合成 PDF | 文档解析、证据检索与 WBS 来源 |

主需求正文可直接使用：

> 为虚构医疗软件管理端提供登录失败计数与账号锁定能力。连续五次登录失败后锁定十五分钟；锁定期间拒绝登录，锁定到期后允许重新尝试。登录失败、锁定及恢复相关操作应保留可追溯记录。验收包括正常登录、连续失败、锁定期间访问、到期恢复及权限边界。本需求仅描述合成软件场景，不包含真实患者或生产业务数据。

以上“5 次、15 分钟”是本次被交付软件的示例需求，不代表 MedPM-AI 自身登录策略。不要在演示中将两者混为一谈。

## 三 PM 项目组织与 AI 辅助交付

### PM 1 创建项目并授权协作者

**入口：**首页 → 主导航“项目”。建议用时 2 分钟。

1. 登录 PM，展示导航中的当前用户、个人资料、风险通知和登出；确认没有“用户管理”“审计”入口。
2. 在项目列表点击“创建项目”，进入独立页面填写“项目名称”“项目描述”并提交。成功后回到项目列表，展示创建成功提示和已更新的项目卡片。
3. 点击新项目名称或成功提示中的“进入项目”，进入任务看板，再点击“项目成员 →”。展示独立的返回链接、负责人信息和成员表格。
4. 在“选择成员”中选择本次 MEMBER，点击“添加成员”；再加入 QA。使用实际要演示的账号，不默认其他同名用户已有访问权。
5. 核对两位协作者进入已授权成员表。展示负责人不可通过“移出”撤销访问权；此处不实际移除后续演示者。

**预期结果：**项目可见，成员表对齐且显示系统角色、访问权和操作。MEMBER/QA 登录后能看到该项目。

**讲解：**“系统角色和项目授权分开设计：QA 的职责是验证，但只有获得项目授权后才能查看本项目。授权变更有审计记录，移出成员也不会删除其历史贡献。”

### PM 2 建立需求与正式任务

**入口：**项目看板 →“维护需求与测试追溯 →”。建议用时 3 分钟。

1. 在“新建需求”填写 `REQ-DEMO-01` 及准备好的正文。为了演示已批准需求的追溯规则，将“需求状态”选为 APPROVED，再点击“创建需求”。
2. 返回看板，点击“创建任务”进入独立页面，填写主任务 `TASK-DEMO-01`，在“关联需求”中选择 `REQ-DEMO-01`。提交后返回看板，展示成功提示及待办列中的新任务。
3. 在主任务卡片的“分配负责人”中选择已加入项目的 MEMBER。
4. 再经独立创建任务页创建 `TASK-GAP-01`，暂选“不关联需求”。说明这是为演示链路检查而主动留下的合成缺口。
5. 点击主任务标题进入详情，展示关联需求、测试列表及审计时间线。

**预期结果：**主任务有负责人和关联需求；缺口任务暂未关联需求；创建和分配可追溯。

**讲解：**“正式任务需要明确需求来源。系统允许交付过程中存在未补齐的关联，但合规扫描会把缺口明确列出，供团队整改。”

### PM 3 PDF 上传 解析与证据检索

**入口：**项目看板 →“项目文档 →”。建议用时 3 分钟；解析建议提前完成。

1. “选择 PDF”选择合成需求文件，勾选合成数据确认，点击“上传文档”。
2. 核对文件名、大小、SHA-256 和“可下载”状态。上传成功不等于解析已成功。
3. 如需现场解析，阅读云处理确认，勾选后点击“开始解析”。只在确认该文件可发送给已配置的模型/解析服务时操作。
4. 点击“刷新解析任务”；成功后点击“预览解析结果”，查看文本和结构化来源。解析需要等待，不连续重复申请新版本。
5. 在“检索项目文档”输入 `登录失败 锁定 审计`，点击“检索文档”。
6. 展示命中文件、版本、页码和片段，点击文件名查看引用正文，再按页面链接返回。

**预期结果：**检索结果带来源。无页码的来源明确显示“无页码”；语义检索不可用时可显示关键词降级。尚未解析或分块就绪的文件不会参与检索。

**讲解：**“AI 使用的是可定位的需求证据，而不是一个无法追溯的文件名。检索记录查询、命中来源、耗时及是否降级。重新解析也不能改写已经保存的建议证据快照。”

**现场降级：**云端解析未完成时展示预先解析好的合成文件；没有任何成功解析数据时只展示上传和下载，跳过 RAG 命中，不宣称关键词检索可以代替 PDF 解析。

### PM 4 WBS 分解与工期建议

**入口：**项目看板的项目功能导航 →“智能 WBS 分解 →”，进入独立的“WBS 与工期建议”页面。建议用时 3 分钟。

需求输入建议：

> 请根据本项目的合成需求文档，将登录失败计数、账号锁定、到期恢复及审计追踪拆解为四至六个软件交付任务。包含设计、实现与验证任务，给出预计工时、建议角色和合理前置依赖。验收重点是连续失败达到阈值后的锁定、锁定到期恢复及操作可追溯；所有内容仅用于虚构软件项目演示。

1. 填入需求并勾选合成数据及模型处理确认，点击“生成 WBS 建议”。
2. 先展示“待 PM 确认”、建议工时、角色、文档证据与历史任务依据。此时不把建议当作已创建任务。
3. 展示 PDF 引用为无外框的下划线链接；点击一处来源并返回。
4. 按前置顺序采纳一条无未处理依赖的建议。后置任务若尚不可采纳，展示中文原因和“查看前置任务”链接。
5. 点击“采纳为任务”，观察该建议卡片消失，再点击“查看任务看板 →”核对正式任务。后置建议的依赖状态随刷新更新。
6. 可拒绝一条不适合的独立建议，说明拒绝决定保留记录。不要把被其他任务依赖的建议随意拒绝后仍期待后置任务可采纳。
7. 若要将 AI 生成任务纳入主需求链路，进入追溯页面，在“任务关联需求”中明确选择需求并“保存关联”；采纳 WBS 不等于所有追溯关联已经补齐。

**预期结果：**建议默认待确认；正式任务仅在采纳后创建；待确认卡片清理且刷新后不回流。证据不足时如实显示没有历史或文档依据。

**讲解：**“模型提出拆解和估算，PM 承担确认责任。模型建议角色不是自动分配负责人；工时建议也不是交付承诺。依赖约束可避免团队按错误顺序建立任务链。”

**现场降级：**模型失败时展示中文错误与独立的关键词检索提示，输入保持不变，允许缩小范围重试或点击“手动创建任务”。输出结构无效时后台最多自动纠正一次，仍失败则不写入建议。继续用主任务完成演示，不把空建议或手工任务描述成 AI 成功输出。

### PM 5 排期 容量与手动风险扫描

**入口：**项目看板 →“排期与人员容量 →”。建议用时 3 分钟。

1. 选择本周的统计周，确认按 UTC 周一至周日统计。
2. 为未完成的主任务设置开始日期、截止日期和预计工时，点击“保存排期”。
3. 为了稳定展示资源风险，让该任务在本周内开始和截止，预计工时填 8 小时；对应成员本周容量填 2 小时并“保存容量”。务必让日期落在当前被统计周，不照抄已经过期的固定日期。
4. 展示“计划工时”“容量”“超出容量”。其他任务也会影响汇总，最终数字以实际页面为准。
5. 返回看板，经“风险预警 →”进入独立页面，再点击“扫描项目风险”。展开查看容量、截止日期或前置任务等依据。
6. 说明扫描没有改变任务状态。对一条风险点击“已处理”或“忽略”，观察处置反馈；该按钮记录处置决定，不自动修改排期或释放容量。
7. 如需展示实质整改，返回排期页面调整本周容量或任务计划，再扫描并比较新依据。旧预警是历史快照，不保证被自动删除。

**讲解：**“这个风险 Agent 当前以可解释规则执行，不依赖语言模型来决定任务状态。团队能检查为什么预警，实际排期仍由 PM 手动调整。”

**演示边界：**未配置容量与容量为零含义不同。任务缺少日期、工时或统计不完整时，不能把‘无法完整判断’讲成‘没有风险’。

### PM 6 自动风险扫描与个人通知

**入口：**看板 →“风险预警 →”→“自动风险扫描”；主导航 →“风险通知”。选演 2 分钟。

1. 确认风险后台进程运行，且项目未处于暂停或已完成状态。
2. 勾选“启用自动风险扫描”，选择页面提供的间隔，点击“保存扫描计划”。最短间隔为 15 分钟，不填写页面不存在的秒级间隔。
3. 点击“刷新自动扫描状态”，展示待执行、运行或已完成的记录。首次启用可被后台调度，无需现场等待完整的下一周期。
4. 进入“风险通知”，点击“查看风险依据”；随后“标为已读”。
5. 说明已读只改变通知状态，风险仍需在看板人工处置；没有新风险或被去重时，不保证每次扫描都新增通知。

**讲解：**“自动化负责主动发现和通知，人工负责决策。通知按当前用户隔离，不是发给全部 PM 的广播。”

演示结束后，可按需要关闭本次项目的扫描计划，避免无意持续产生演示提醒。

## 四 MEMBER 执行任务与交付留痕

### MEMBER 1 个人任务执行

**前置：**PM 已授权该账号并分配主任务。入口：主导航“项目”→ 演示项目看板。建议用时 2 分钟。

1. 先登出 PM，再登录 MEMBER，展示顶部角色及简化后的导航。
2. 找到分配给本人的 `TASK-DEMO-01`。确认卡片显示本人姓名。
3. 点击“开始 / 恢复”，任务从待办移到进行中。
4. 可选：点击“标记受阻”，说明阻塞原因需团队协作处理；再“开始 / 恢复”回到进行中。
5. 在“实际工时”填 `3.5`，点击“完成”。不填工时时完成按钮不可正常完成该动作。
6. 点击任务标题，查看状态、关联需求和审计时间线。

**预期结果：**主任务成为 DONE，记录实际工时和完成时间。成员只能更新自己被分配的任务，不展示 PM 的 WBS 与风险操作面板。

**讲解：**“业务数据来自实际执行，而不是只由 AI 预测。真实填写的合成工时会成为未来估算的依据；状态更新和审计在同一事务中保存。”

### MEMBER 2 查看需求与协作证据

**入口：**任务详情；或看板 →“维护需求与测试追溯 →”“项目文档 →”。选演 1 分钟。

1. 查看主任务关联的需求和测试结果，说明 MEMBER 可以了解验收条件，但不代替 QA 维护测试用例。
2. 若已备好解析数据，查看或检索需求文档，点击来源核对版本和正文。
3. 返回看板，指出他人任务没有供当前 MEMBER 使用的状态操作入口。不要为展示权限而修改他人的数据。

**讲解：**“执行者能查看工作依据，修改权限则按职责收紧。任务完成并不自动代表测试通过。”

## 五 QA 测试追溯与合规审查

### QA 1 创建测试用例并记录结果

**前置：**PM 已将 QA 加入演示项目。入口：主导航“项目”→ 看板 →“维护需求与测试追溯 →”。建议用时 3 分钟。

1. 登出上一角色，登录 QA。展示主导航“审计”入口及没有“用户管理”入口。
2. 找到 `REQ-DEMO-01`，在“新增测试用例”输入 `TC-DEMO-01 连续失败达到阈值后锁定`，测试结果先选 NOT_RUN，点击“创建测试用例”。
3. 为展示“任务完成不等于测试完成”，首次合规扫描前保留 NOT_RUN 状态。
4. 完成 QA 3 的首次扫描后回到这里，将结果设为 PASSED，点击“保存测试用例”。
5. 展示表单旁包含用例名称的成功提示和短暂高亮；需要时点击“返回项目看板”。

**预期结果：**测试用例属于该需求，结果更新有审计记录；失败保存时输入保留，不应通过重复点击推测是否已保存。

**讲解：**“执行完成与验证通过是两种不同的事实。只有把测试结果关联到需求，才能判断交付链路是否闭合。”

### QA 2 需求版本适配复核

**入口：**需求与测试追溯页面中任务和测试用例的版本复核区域。建议用时 2 分钟。

1. 查看“当前需求版本”和“已复核版本”。新任务或新用例可能尚未复核。
2. 对主任务填写“版本复核说明”，例如“已核对登录失败计数与锁定行为，适配当前合成需求版本”，点击“确认适配当前需求版本”。
3. 对测试用例执行同样的适配复核。保存测试结果不会自动代替需求版本复核。
4. 选演：由 PM 修改主需求正文并“保存需求”，观察版本递增；重新登录 QA，展示原复核版本过期，再核对并复核新版本。

**预期结果：**复核记录含当前需求版本、复核者和时间；需求变更后，旧版本适配不能直接充当新版本证据。

**讲解：**“追溯不仅是连了一个 ID，还要证明任务和测试对应哪个版本。需求变更会使旧复核失效，需要重新确认适配。”

### QA 3 合规 Agent 发现问题并形成整改闭环

**入口：**主导航“审计”→“审计日志与合规审查”。建议用时 4 分钟。

1. 在“项目”选择框选择演示项目，无需输入 UUID。第一次不设置操作人或时间筛选，避免人为缩小审计来源。
2. 点击“生成合规摘要”。展示扫描时间、覆盖范围、摘要状态和规则发现；初始摘要为 PENDING。
3. 对照演示数据解释发现项，而不机械承诺出现固定数量：

| 发现项 | 触发条件 | 演示中的对应操作 |
| --- | --- | --- |
| TASK_WITHOUT_REQUIREMENT | 任务未关联需求 | PM 故意留下的 `TASK-GAP-01`，以及尚未关联的 AI 任务 |
| DONE_TASK_WITH_UNPASSED_TEST | 已完成任务对应需求仍有未通过测试 | MEMBER 完成主任务、QA 的用例仍为 NOT_RUN 时 |
| TASK_REQUIREMENT_REVIEW_STALE | 任务未复核当前需求版本 | QA 尚未进行主任务版本适配复核时 |
| TEST_REQUIREMENT_REVIEW_STALE | 用例未复核当前需求版本 | QA 尚未进行用例版本适配复核时 |
| REQUIREMENT_WITHOUT_TEST | 有效需求没有测试用例 | 首次扫描早于用例创建时 |
| APPROVED_REQUIREMENT_WITHOUT_TASK | 已批准需求没有关联任务 | 只有实际留下这种缺口时才展示 |

4. 展开一个发现，点击关联业务证据；若有“审计记录 …”链接，查看原始记录，再返回审计页。没有来源记录时如实说明，不编造来源。
5. 对未复核发现填写“问题复核说明”，例如“确认该合成任务缺少需求关联，交由 PM 补齐”，选择页面提供的确认/驳回决定并“提交问题复核”。
6. 如需复核摘要，选择“摘要决定”，填写说明“认可本次扫描结论，保留列出的整改事项，不构成发布批准”，点击“提交摘要复核”。
7. 做一次真实整改：PM 在追溯页给 `TASK-GAP-01` 补关联需求；QA 将主用例保存为 PASSED，并完成任务和用例版本复核。
8. 再次由 QA 生成摘要，对比目标问题是否消失或变化。AI 任务、其他需求可能仍有问题，不要求所有发现归零。
9. 点击“查询历史摘要”，打开前一次记录，说明旧扫描结果保留，不被本次整改重写。

**预期结果：**发现、复核、业务整改、重新扫描分别留痕。摘要采纳或问题确认不自动修正业务数据。采纳摘要也可保留未整改发现，因为它表示认可结论。

**讲解：**“规则检测追溯断点，模型在可用时辅助组织摘要，QA 决定是否认可。系统保留检查时的快照，让审计人员知道当时看到了什么、后来改了什么。”

**现场降级：**语言模型不可用时展示规则降级标识和实际规则结果；不将规则输出描述成模型成功调用。覆盖不完整或审计来源被截断时，按页面提示补查，不能宣布全部通过。

### QA 4 查询审计与导出证据

**入口：**主导航“审计”；项目看板 →“合规导出 →”。建议用时 2 分钟。

1. 在审计页面选中项目，“操作类型”可输入 `TASK_STATUS_CHANGED`，点击“查询日志”，展示 MEMBER 的状态变化及 before/after。
2. 清空操作类型，再查询 `AI_SUGGESTION_ACCEPTED` 或 `TEST_CASE_UPDATED`，展示不同职责的操作记录。没有执行过相应动作时不期待存在记录。
3. 经主导航“项目”进入同一项目看板，点击“合规导出 →”。
4. 选择“追溯矩阵 CSV”，点击“生成并下载”；展示导出记录的状态、SHA-256 和时间。
5. 选演：“证据包 JSON”→“生成并下载”。说明可从已有导出记录再次“下载”。
6. 返回审计页面查看导出相关事件，解释谁在何时导出了哪个项目及范围。

**预期结果：**CSV 包含需求、任务、测试的追溯矩阵；JSON 包含当前业务快照、指定范围审计事件及最近审计摘要。时间范围只过滤审计事件，不把当前业务快照变成历史快照。

**讲解：**“导出也是受控业务动作，下载文件并不是审计链路的终点。我们同时保留操作者、范围和校验信息。”

MinIO 不可用时生成/下载可能失败；只展示已有元数据不等于证明文件仍可下载，也不现场删除失败对象来伪装成功。

## 六 ADMIN 账号治理与权限留痕

### ADMIN 1 用户生命周期

**入口：**登录 ADMIN → 主导航“用户管理”。建议用时 3 分钟。

1. 展示用户列表、角色/状态筛选、姓名或邮箱搜索以及分页。历史测试身份可能为 DISABLED，演示时可筛选 ACTIVE；不宣称审计关联账号已被物理删除。
2. 点击“创建用户”，使用专门演示账号，如 `role-demo-20261016@medpm.local`，填写合成姓名、MEMBER 角色和独立演示密码，点击“确认创建”。密码不展示在投屏画面中。
3. 如演示注册审批，可先让访客经主导航“注册账号”提交，再由 ADMIN 查询该 PENDING 用户并“激活”；若当前注册需要邀请码，使用已配置的邀请码，现场没有则跳过这条分支。
4. 在专用演示用户行调整角色，点击“修改角色”，检查确认弹窗的变更前后值，再“确认变更”。
5. 只禁用专用演示账号，说明会撤销其有效会话、保留历史记录；随后根据演示需要“重新启用”。重新启用后需重新登录。
6. 指出当前 ADMIN 账号的角色、状态操作不可用于修改自己。不要禁用当前 PM、QA、MEMBER，打断主线演示。

**预期结果：**创建、激活、角色变化、禁用均有明确结果；历史业务不随账号禁用删除。用户角色变化不自动赋予项目成员资格。

**讲解：**“账号治理控制的是持续有效的权限，不只是隐藏按钮。角色或状态变化需要后端重新检查；会话撤销与审计共同保证权限变更可追溯。”

### ADMIN 2 全局审计与项目授权监督

**入口：**主导航“审计”；或“项目”→ 选项目 →“项目成员 →”。选演 2 分钟。

1. 在审计页不限定项目，查看有权限的全局事件；按页面操作类型筛选用户角色或状态变更。以实际事件名称为准，不假定所有历史事件都属于当前项目。
2. 展示管理员能看到“用户管理”和“审计”；MEMBER 没有这两个入口，QA 仅有审计入口。
3. 进入演示项目的成员页面，展示 ADMIN 可维护授权。只有预先准备的专用协作者才用于移出与重新加入演示。
4. 如需要演示撤权效果，将该协作者移出后，让其刷新项目列表并验证原项目不再可访问；验证后重新加入。不删除历史任务、审计或导出记录。

**讲解：**“管理权限用于治理账号与访问，不替代项目经理的交付决策，也不替代 QA 的质量复核。”

## 七 推荐演示顺序

### 7.1 十五分钟版本

| 时段 | 角色 | 现场内容 | 要展示的证据 |
| --- | --- | --- | --- |
| 0–1 分钟 | 访客/PM | 首页三个入口、登录与当前角色 | 角色导航与实际入口 |
| 1–5 分钟 | PM | 使用备好项目，查看成员和需求；展示已解析文档；生成并采纳一条 WBS 建议 | 来源、待确认、依赖提示、卡片移除和正式任务 |
| 5–7 分钟 | PM | 查看本周容量并手动扫描风险 | 容量依据，任务状态未自动变化 |
| 7–9 分钟 | MEMBER | 执行主任务并填写实际工时，查看详情时间线 | 本人任务权限、工时、审计 |
| 9–13 分钟 | QA | 创建/更新测试用例、版本复核、合规扫描与复核 | 需求—任务—测试链路与发现项 |
| 13–14 分钟 | QA | 下载 CSV 或展示可下载的既有合成证据包 | 导出范围、哈希和审计 |
| 14–15 分钟 | ADMIN | 查看专用用户及治理事件，概括角色分离 | 权限变更留痕 |

限时版将解析与成员准备提前完成；不现场等待云端任务，不为赶时间省略人工作出的确认动作。若要体现整改前后对比，再预留约 3 分钟完成跨角色补链与重新扫描。

### 7.2 完整走查版本

按 PM 1–4 → MEMBER 1 → QA 1（先 NOT_RUN）→ QA 3 首次扫描 → QA 1 保存 PASSED → QA 2 → PM 补齐缺口任务关联 → QA 3 再扫描/历史摘要 → PM 5–6 → QA 4 → ADMIN 1–2 执行，约 30–40 分钟。

把风险演示放在成员完成任务后时，使用另一条未完成任务，先分配给演示成员，再设置本周排期与容量；风险分析会跳过 DONE 任务，不能拿已完成主任务强行制造在途风险。

## 八 常见现场问题与继续方式

| 现象 | 先检查 | 继续方式 |
| --- | --- | --- |
| 看不到项目 | 当前角色、是否已授权、是否进入了正确浏览器登录态 | PM/ADMIN 在成员页面补授权，再让目标账号刷新 |
| 采纳按钮不可用 | 前置建议是否已采纳 | 通过前置任务链接按顺序操作；缺失/被拒绝则重新生成或人工创建并核对依赖 |
| PDF 上传成功但检索无结果 | 解析是否成功、分块是否就绪、检索词是否匹配 | 展示已有成功版本；不要靠反复上传解决后台进程未启动 |
| 没有语义检索 | embedding、Milvus、当前版本索引 | 如实展示关键词降级；没有命中不等于没有需求 |
| WBS 无建议 | 模型配置/服务及页面提示 | 用手工任务继续主线，明确 AI 环节未成功 |
| 风险为空 | 任务是否已完成、日期/容量是否落在当前统计周、是否确有风险 | 使用预备的未完成任务；无风险结果不强行解释为故障 |
| 自动扫描无新通知 | 后台进程、计划、项目状态、风险去重 | 展示调度状态或使用手动扫描，不承诺每次都新增提醒 |
| QA 扫描仍有发现 | 其他 AI 任务未关联、用例仍未通过、版本复核遗漏 | 逐条解释，比较目标问题变化，不宣称全项目已通过 |
| 导出失败 | MinIO、项目授权及文件状态 | 说明实际失败；用已有合成文件演示结构时标明其生成时间和项目 |
| Edge 窗口意外切换 | 普通/无痕窗口、最近点击的按钮、文件选择或下载提示 | 回到原窗口核对当前账号；未确认保存结果前不重复提交 |

## 九 收尾讲解与验收清单

收尾可用：

> PM 用需求和证据组织交付，成员负责实际执行，QA 验证并检查追溯，管理员治理权限。三个 Agent 嵌入这些职责：WBS 提出建议，风险主动发现问题，合规扫描指出链路缺口。关键决定由人确认，并保留其依据和审计记录。

离场前核对：

- 演示项目及角色授权明确，未误改已有走查项目。
- 采纳的 WBS 建议对应正式任务；其需求关联和实际负责人已核对。
- 至少展示一条带来源的文档引用，或如实说明该环节未具备运行条件。
- 至少展示一次状态变更、测试保存及审计记录。
- QA 复核与 PM 决策没有混用角色；摘要采纳没有被描述为合规批准。
- 需要时关闭本次自动扫描计划并登出演示账号；保留审计记录。
- 未展示真实患者信息、生产数据、密码或服务密钥。

本手册说明可演示的产品行为，不构成医疗法规符合性认定。当前没有完整电子签名、法规认证或自动发布批准能力；不在演示中声称已经实现。
