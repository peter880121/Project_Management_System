## 人员任务优先展示（2026-10-22）

点击人员后默认进入其当前负责的任务，使用 `taskView=CURRENT`、`taskSort=FOLLOW_UP`。先展示进行中、逾期和受阻数量，再展示任务明细；统计图表与历史办理记录默认折叠。任务同时进行中和逾期时只占一行，保留两个状态提示。历史动作显示中文名称，审计编号与操作时角色证据继续保留；历史角色缺失仍显示未知。

- 当前待跟进：PLANNING / ACTIVE 项目中，本人负责的 TODO / IN_PROGRESS / BLOCKED 任务。
- 冻结积压：其他生命周期项目中的本人未完成任务，历史到期不计作当前逾期。
- 全部任务：保留历史查询能力；取消任务仍需明确选择取消状态。

当前与冻结视图查询完整存量，不受最近创建日期限制。日期范围在这些视图只影响历史办理记录；全部任务可按创建或完成日期筛选。人员概况卡始终表示当前存量，并保留项目、人员及业务筛选范围。

数据库先排序再分页：当前逾期按到期日从早到晚，其后依次为进行中、受阻、待办；同组按到期日排序，未排期靠后，以 ID 保持稳定。香港自然日当天到期不算逾期。URL 保存任务视图与排序，查询切换立即隔离旧结果，失败可重试。排序、分页、导出共用权限与筛选条件，不扩大人员或项目访问范围。

本次无数据库迁移、无新增依赖。实现涉及 `src/components/dashboard/decision-center.tsx`、`src/modules/dashboard/decision-schema.ts`、`decision-repositories.ts`、`decision-service.ts`；验证位于 `decision-schema.test.ts`、`tests/integration/decision-center.test.ts`、`e2e/decision-center.spec.ts`，覆盖跨页排序、香港午夜、冻结积压、日期范围、越权查询、导出审计及浏览器筛选持久化。

## 范围与权限

ADMIN / PMO 全局；PM 仅负责人或有效成员所在项目；QA / MEMBER 返回 403。传入项目、人员 ID 不会扩大范围；越权项目查询返回空集合。查询、人员详情、聚合、导出始终使用权限条件与筛选条件的交集。

周报另有更严格的分区规则：PM 必须是该项目负责人，参与项目不自动获得同事周报权限。PM 的周报统计不暴露全局应报名册或全局缺报分母。

## 视图与口径

| 维度 | 指标与明细                                                                                                                                             |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 项目 | 生命周期分布、进行中/暂停/待验收、有效任务完成率、逾期/受阻/待排期、本轮签名与交付物缺口、未关闭需求、待客户确认、待审变更、近七日待处理预警、状态起点 |
| 任务 | 状态/阶段/负责人、计划与实际日期和工时、有效样本工时偏差、按期完成率、逾期天数与 1–3/4–7/7+ 天分层、冻结积压、未分配/待排期/交付物缺口筛选             |
| 需求 | 正式生命周期、优先级、计划/实际日期、负责人、批准/草稿版本、有效任务覆盖、逾期与待审变更；历史未治理需求及期间原始诉求分别解释                         |
| 人员 | 当前系统角色、负责项目/参与项目、活跃任务/逾期任务、活跃正式需求、未完成任务预计工时、冻结项目任务、真实办理事件                                       |
| 周报 | 应报/首次报送/未报/准时/迟报、待阅分区、本人申报工时、报告问题；支持周、项目、作者及提交时角色过滤                                                     |

人员名称可以下钻，按「当前负责 / 项目参与 / 历史办理」查看项目、任务和需求。当前负责分别取 `Project.ownerId`、`Task.assigneeId`、`Requirement.ownerId`，不能用创建人或签名人代替。QA 不会因角色而自动持有所有项目审核工作。

历史办理只取明确的业务审计动作，不把聊天/查询行为算成交付。展示所选期间最近 20 条办理记录。`AuditLog.actorRole` 从本次迁移开始由数据库插入触发器捕获；旧记录保持 NULL，界面标明历史角色未知，绝不根据当前角色回填。

任务与需求分别统计，共享任务通过 EXISTS 判定多对多覆盖，不因关联多个需求而放大数量。两者不相加为人员总负荷。

取消任务默认不计有效完成率和活跃工作；可明确筛选取消状态查看历史。活跃资源只计 PLANNING / ACTIVE 项目；暂停、待验收、取消、归档项目的未完工作另列冻结积压。

工时偏差只用 DONE 且两侧工时均大于 0 的配对样本，并展示覆盖数。没有可比样本显示“—”。未完成任务预计工时不是剩余工时；不以可见的部分项目工作推断全局空闲率，也不生成人员绩效分数。

## 时间与历史

URL 保存维度、人员、职责、项目、状态、搜索、日期和分页。当前存量与按新建/完成时间筛选分开。新建/归档/审计时间以香港自然日转换成 UTC 左闭右开查询；任务、需求的实际完成日期采用日历日期边界查询。

项目状态分布和明细用同一查询范围。历史观测只随权限与项目范围过滤，不用今天的状态筛选去改写过去的观测。每页 20 条，项目选择器最多 501 条；更大项目组合仍可通过合法项目 ID 和名称查询，后续可改为远程项目选择器。

`DecisionSnapshot` 记录每天首次真实观测的项目状态、有效任务、完成任务、执行项目逾期和未关闭需求。ADMIN / PMO 点击「采集今日快照」启动，重复操作不会覆盖同日数据。界面最多显示所选期间 92 个观测日。不补造历史，不把未采集日补零，也不把首次观测冒充日终快照。本次没有新增常驻采集服务，自动定时采集需要部署侧进一步配置。

## 数据访问与导出

- `GET /api/dashboard/stats` 保持兼容。
- `GET /api/dashboard/insights` 获取新维度指标、分布、分页明细、人员身份及办理证据。
- `POST /api/dashboard/insights` 审计后导出当前筛选的本页 JSON，明确不冒充全量导出。
- `POST /api/dashboard/snapshots` 仅全局管理可采集当前日快照。
- 周报统计复用 `/api/weekly-reports/stats`。

使用 Prisma count/groupBy 和参数化 SQL，由 MySQL 完成 COUNT/SUM/EXISTS/JSON_TABLE 聚合，不拉全量业务数据到 JS 汇总。只对已分页明细和已聚合数字做格式化。客户端取消过时请求并隔离请求序列，查询失败先清空旧统计，避免范围切换时沿用其他人的结果。
