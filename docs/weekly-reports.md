# 个人周报

入口：侧边栏「个人周报」(`/weekly-reports`)。所有有效非系统账号均可使用，不需要额外服务或 LLM 配置。

## 工作闭环

1. 选择周内任意日期，点击「写周报」；同一账号同一自然周只生成一份记录。
2. 添加项目分区或非项目工作，填写摘要及完成、进行中、问题与协助、下周计划。目标日期与个人申报工时可选。
3. 「汇总我的工作」查询本人当前负责的任务/需求、期间新增资产和实际办理审计。候选项需要逐条采纳；不自动覆盖正文，不自动提交、不修改业务状态。
4. 草稿停笔 1.5 秒自动保存，也可手动保存。保存失败保留输入并提示；离开页面有未保存内容时提示。保存带 `expectedVersion`，冲突返回 409。
5. 本人确认提交，形成 SHA256 校验的不可改写 JSON 快照。未来周仅允许草稿，不能提前计入报送。
6. 项目负责人按项目分区阅知或说明退回；本人也可填写原因发起修订。重新提交产生新版本，旧版本保留。其他项目分区没有变化时原阅知证据继续适用。
7. 导出 JSON 仅包含当前权限允许的分区与版本，交付文件前必须成功记录导出审计。

“已阅”是管理沟通记录，不替代验收审批、电子签名或任务工时确认。

## 权限与冻结

| 身份 | 查看范围 | 操作 |
| --- | --- | --- |
| 本人 | 本人整份周报、历史提交及反馈 | 编辑草稿、采纳候选、提交、说明修订、导出 |
| 项目负责人 PM | 自己负责项目的已提交分区 | 阅知、说明退回、导出可见分区 |
| ADMIN / PMO | 全局周报 | 阅知、退回、人员台账与豁免管理 |
| 其他参与成员 | 不因参与同项目而获得他人周报权限 | 仅本人周报 |

禁止自阅作为管理确认。非项目工作不向项目 PM 暴露。分区、版本、反馈、导出、统计均执行同样的项目过滤。来源链接不授予额外的项目权限。

周报是用户管理记录，`WeeklyReportSection.projectId` 只是项目引用，明确列入冻结策略的运营记录例外。可补记已归档或暂停项目的历史工作；保存周报没有任何路径修改 Task、Requirement、Deliverable、MeetingRecord，也没有新增项目写入绕过。

## 时间和工时

- 香港时间周一 00:00 至下周一 00:00，数据库以 UTC `DATETIME(3)` 保存左闭右开区间。
- 默认次周一 12:00 截止，可配置 `WEEKLY_REPORT_DEADLINE_HOUR_HK`（0–23）。已采集的截止时间不随配置追溯变化。
- 本周首次访问周报或周报统计时，采集当前有效非系统账号的应报快照。人员随后停用或换角色不会改变已采集的分母。
- 尚未启用周报的历史周不根据今天的员工名单反推；应报、未报率显示不可用。没有访问且没有调度采集的周，不宣称已完整采集。
- 全局管理可在「周报台账 → 应报人员与豁免台账」登记说明豁免，操作有审计。首次提交时间判定准时/迟报，后续修订不改变首次报送时间。
- 个人申报工时最多两位小数，每周合计不超过 168 小时。`Task.actualHours` 是任务累计实际工时，绝不自动归入完成当周，也不与申报工时相加。同一事项请勿重复申报。
- 问题项计数表示周报中报告的问题，不代表真实业务风险已验证或已关闭；协助对象、影响与整改说明在正文记录，目标日期独立保存。

## 数据与 API

新增 `WeeklyReportPeriod`、`WeeklyReportExpectation`、`WeeklyReport`、`WeeklyReportSection`、`WeeklyReportItem`、`WeeklyReportRevision`、`WeeklyReportReview`。

| API | 行为 |
| --- | --- |
| `GET/POST /api/weekly-reports` | 权限过滤的分页列表 / 建立本人草稿 |
| `GET/PATCH /api/weekly-reports/[id]` | 分区过滤详情 / 乐观锁保存 |
| `POST .../[id]/collect` | 有界、去重的本人工作候选 |
| `POST .../[id]/submit` | 校验当前权限及来源，提交不可改写快照 |
| `POST .../[id]/review` | 管理阅知或说明退回单个分区 |
| `POST .../[id]/revise` | 本人说明修订，保留旧提交 |
| `POST .../[id]/export` | 审计后返回权限内 JSON |
| `GET /api/weekly-reports/stats` | 按周/项目/作者/提交时角色聚合 |
| `GET /api/weekly-reports/roster` | 全局管理分页应报台账 |
| `POST /api/weekly-reports/exempt` | 全局管理说明豁免 |

输入严格 Zod 校验；所有写入在事务中；角色和来源在提交事务再次校验。来源校验按类型批量查询，避免按工作项逐个查询。候选每类最多约 200 条并提示截断；汇总只取有权项目，不把整个业务库加载到前端。

对象键规范排序后计算 SHA256，兼容 MySQL JSON 重排。数据库触发器禁止更新/删除提交快照、阅知证据及周期间记录，已提交正文也不可直接更新。审计覆盖草稿、保存、提交、修订、阅知、退回、豁免和导出。

## 迁移与验证

迁移：`prisma/migrations/20261030000000_weekly_reports`，仅新增表，FK 为 Restrict，创建可重复执行。`rollback.sql` 仅在没有任何周报数据时允许回退，产生记录后应前向修复，禁止通过回退删除证据。

`node scripts/verify-weekly-migration.mjs --apply` 限定本地开发/演示库，部署迁移并比对既有业务/审计记录数量。验证输出在 `output/weekly-reports/migration-verification.json`。测试使用独立的 `medpm_test_ia_*` 数据库，不向演示库写入测试周报。

测试覆盖：周跨月/跨年边界、MySQL JSON 规范哈希、并发版本、重复提交、审核与导出跨项目隔离、自阅拒绝、权限撤销、审计故障回滚、数据库证据不可改写、冻结项目只读引用、稳定应报分母，以及页面填写/汇总/提交/修订闭环。
