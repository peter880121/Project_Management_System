# 会议纪要附件

会议创建表单支持同时选择附件；草稿和已定稿纪要的详情中也可追加附件。格式为 PDF、DOCX、TXT、TEXT、MD，PDF/DOCX 不超过 20 MB，文本不超过 5 MB；单次最多 10 个，每份会议最多 20 个有效附件。

## 存储与权限

- 原件保存在现有 MinIO 中，`Document.meetingAttachmentId` 关联 `MeetingRecord`。既有 `MeetingRecord.documentId` 继续专用于正文知识库源，二者互不覆盖。
- PM/ADMIN 可上传，有权限的会议读者可下载；草稿附件仅 PM/ADMIN 可读。附件在创建事务中继承会议可见角色，直接文档 URL 同样检查项目成员资格、会议范围和草稿状态。
- 项目文档列表不混入会议附件，私密会议附件不能被重新挂为交付物以放宽可见范围。项目暂停、取消、归档和验收锁定沿用现有冻结机制。
- 定稿后正文仍只读，附件采用追加方式保留证据，不提供覆盖、删除原件的入口。

## 事务、审计与失败恢复

复用文档上传的 UPLOADING → AVAILABLE/FAILED 流程；确认 AVAILABLE 和 `MEETING_ATTACHMENT_ADDED` 审计在同一事务提交，保留文件名、类型、大小与 SHA-256。下载核验哈希并记录导出审计；超过 10 分钟的中断上传支持校验恢复，恢复成功补写附件审计。

创建纪要和上传文件是两个明确的提交步骤。部分文件失败会提示“会议已保存”，保留失败文件供重试，不重复创建会议或重复上传已成功的文件。网络结果不明时保留幂等键，先刷新核实；已标为 FAILED 的文件需重新选择上传。附件上限在持有项目锁的事务中检查，防止并发突破。

上传不自动替换正文、提取行动项或同步知识库；现有“同步至知识库”仍处理定稿正文和行动项。附件解析及 RAG 底层也检查会议状态及角色，草稿不会进入检索结果。

## API 与迁移

- `GET /api/projects/:projectId/meetings/:meetingId/attachments?page=1`：每页 20 条，不暴露对象存储密钥或路径。
- `POST` 同路径：复用 `file`、`syntheticOnly`、`uploadKey` 三字段 multipart 协议。
- 下载沿用 `GET /api/documents/:documentId/download`。

迁移 `20261026000000_meeting_attachments` 仅新增可空外键及索引，历史数据保持 NULL，重复执行安全。业务表既有冻结触发器继续生效。回滚仅限尚无附件及相关审计证据的环境；有证据时主动拒绝回滚，避免破坏审计关联。

## 验证

单元测试覆盖文件选择、格式限制、批量部分失败及权限判断；独立 MySQL 集成测试覆盖原件回读、幂等、跨项目/角色隔离、审计回滚、中断恢复、并发上限和数据库冻结。Playwright 覆盖创建时上传、定稿后追加、下载字节一致性、私密/草稿 URL 越权以及部分失败后重试。
